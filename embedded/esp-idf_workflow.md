# ESP32-S3 Development Workflow (ESP-IDF 6.0.3)

## 1. Every Time You Start Development

### Step 1 --- Connect your board

-   [ ] Connect the ESP32-S3 using a USB data cable.
-   [ ] Check that Ubuntu detects it.

``` bash
ls /dev/ttyACM*
```

Expected output:

``` text
/dev/ttyACM0
```

If the port changes, use the newly detected port in all subsequent
commands.

### Step 2 --- Activate ESP-IDF

Open a terminal and run:

``` bash
source ~/.espressif/v6.0.3/esp-idf/export.sh
```

Verify the installation:

``` bash
idf.py --version
```

Expected: ESP-IDF v6.0.3.

> You must activate ESP-IDF in each new terminal where you want to use
> ESP-IDF commands.

### Step 3 --- Open your project

In the terminal:

``` bash
cd ~/blink
```

Or open the project in VS Code:

``` bash
code ~/blink
```

------------------------------------------------------------------------

## 2. Regular Development Workflow

Use this cycle whenever you modify your application.

1.  **Write your code**

    -   Edit `main/main.c` or `main/main.cpp` in VS Code.

2.  **Build your application**

    ``` bash
    idf.py build
    ```

    This compiles the project and generates the firmware binaries.

3.  **Put the ESP32 into download mode**

    -   Hold the **BOOT** button.
    -   Press and release **RESET/EN** while continuing to hold BOOT.
    -   Release **BOOT**.

4.  **Flash your firmware**

    -   Use the reliable flashing command in Section 3.

5.  **Restart the board**

    -   Press and release **RESET/EN** to boot the application.

6.  **Monitor serial output**

    ``` bash
    idf.py -p /dev/ttyACM0 monitor
    ```

    Check application logs, errors, and output.

    Press `Ctrl+]` to exit the serial monitor.

7.  **Repeat**

    -   Modify your code.
    -   Build, flash, and test again.

## 3. Reliable Flashing Command

The normal stub-based flashing process currently fails on this setup.
Use the ROM bootloader workaround below.

### Step 1 --- Activate ESP-IDF and open the project

``` bash
source ~/.espressif/v6.0.3/esp-idf/export.sh
cd ~/blink
```

### Step 2 --- Build the latest firmware

``` bash
idf.py build
```

### Step 3 --- Enter download mode

-   Hold **BOOT**.
-   Press and release **RESET/EN**.
-   Release **BOOT**.

### Step 4 --- Flash the firmware

``` bash
cd build

python -m esptool \
  --chip esp32s3 \
  -p /dev/ttyACM0 \
  -b 115200 \
  --no-stub \
  --before no-reset \
  --after no-reset \
  write-flash \
  --flash-mode dio \
  --flash-freq 40m \
  --flash-size 16MB \
  0x0 bootloader/bootloader.bin \
  0x8000 partition_table/partition-table.bin \
  0x10000 blink.bin
```

A successful flash should report that the data was written and its hash
verified.

### Step 5 --- Return to the project directory and boot

``` bash
cd ..
```

Press and release **RESET/EN** to start the application.

> **Important:** This command uses the three binary files generated by
> your latest build. If you change your code, run `idf.py build` again
> before flashing. The command assumes the serial port is `/dev/ttyACM0`
> and the board has 16 MB flash. Update the port if Ubuntu detects a
> different one.

## 4. Useful ESP-IDF Commands

  --------------------------------------------------------------------------
  Command                                Purpose
  -------------------------------------- -----------------------------------
  `idf.py build`                         Compile the project and generate
                                         firmware binaries

  `idf.py clean`                         Remove build outputs while
                                         retaining configuration

  `idf.py fullclean`                     Completely clear the build
                                         directory

  `idf.py menuconfig`                    Open project configuration

  `idf.py size`                          Show application memory/size
                                         information

  `idf.py -p /dev/ttyACM0 monitor`       Open the serial monitor

  `idf.py -p /dev/ttyACM0 flash`         Flash using the standard ESP-IDF
                                         flashing process

  `idf.py -p /dev/ttyACM0 erase-flash`   Erase the entire flash
  --------------------------------------------------------------------------

> Avoid `fullclean` and `erase-flash` during normal development unless
> you have a specific reason to use them. `erase-flash` removes the
> contents of the entire flash, not just your application.

## 5. Troubleshooting Checklist

When something fails, identify the affected layer before changing
configurations.

  ------------------------------------------------------------------------------------
  Problem                             First thing to check
  ----------------------------------- ------------------------------------------------
  `idf.py: command not found`         Activate ESP-IDF using
                                      `source ~/.espressif/v6.0.3/esp-idf/export.sh`

  Serial port not found               Run `ls /dev/ttyACM*` and check which port is
                                      present

  Permission denied                   Run `groups` and check `dialout` group
                                      membership

  Device not detected                 Run `lsusb`; check the USB data cable and
                                      connection

  OpenOCD error                       Check the JTAG interface and debugging
                                      configuration; JTAG is not required for normal
                                      flashing

  Stub flasher fails                  Use the `--no-stub` ROM-bootloader workaround in
                                      Section 3

  Build fails                         Read the first compiler error in the build
                                      output

  No serial output                    Check the ESP-IDF console configuration,
                                      selected port, and baud rate

  Firmware does not start             Check BOOT/RESET sequence and confirm the board
                                      has exited download mode
  ------------------------------------------------------------------------------------

### Useful diagnostic commands

Check serial devices:

``` bash
ls /dev/ttyACM*
```

List USB devices:

``` bash
lsusb
```

Check recent kernel messages:

``` bash
sudo dmesg | tail -50
```

Check group membership:

``` bash
groups
```

Check the ESP32-S3 flash identification:

``` bash
python -m esptool --chip esp32s3 -p /dev/ttyACM0 -b 115200 flash-id
```
